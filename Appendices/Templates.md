# Templates

These templates are starting points, not forms to fill in. Their purpose is to help you communicate clearly and document decisions effectively. A template that's followed mechanically without thought produces busywork. A template used as a thinking tool produces clarity.

Before using a template, consider what it's trying to accomplish. An issue template exists to ensure the next person who picks up the work has enough context to succeed. A PR template exists to make the reviewer's job easier and to preserve the reasoning behind your changes. If a section doesn't add value for your specific situation, skip it or replace it with something that does.

Your team may already have project-specific templates in `.github/ISSUE_TEMPLATE/` or `.github/PULL_REQUEST_TEMPLATE.md`. Use those if they exist. If they don't serve you well, improve them.

| Template                                            | Purpose                                              |
| --------------------------------------------------- | ---------------------------------------------------- |
| [Feature Issue](Templates/Feature_Issue.md)         | Creating a new feature request or work item          |
| [Bug Report](Templates/Bug_Report.md)               | Reporting a bug with reproduction steps              |
| [Pull Request](Templates/Pull_Request.md)           | Describing changes submitted for review              |
| [Working Agreement](Templates/Working_Agreement.md) | Establishing team norms at the start of an iteration |
| [Exception Report](Templates/Exception_Report.md)   | Documenting a deviation from an expected norm        |
